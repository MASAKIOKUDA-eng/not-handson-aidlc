## 4. 結果に影響しうる要因

- 実施の順番による影響（2 回目のほうが慣れている）：A は 1 回目
- 2 回目に、1 回目で得た知見を使った場面（あれば具体的に）：A は 1 回目のため該当なし（B 側で記入）
- そのほか（時間切れ、ツールの不具合など）：
  - A：依頼者の「確認を進めて」（`records/conversation-a.md` 172 行目）を受けて、Claude が AWS の公式ドキュメントを Web で参照した。また「Skills を調査して」（`records/conversation-a.md` 412 行目）を受けて、スキル「AWS ネットワーク分析」を参照した。依頼者は参考資料を渡していないが、AI が外部の情報を使った点は B と条件が違いうる
  - A：保存先の指示（`records/conversation-a.md` 44 行目）は、Claude がファイルを書いた後に届いた。指示と同じ場所だったため影響はない
  - A：会話ログは `/export` ではなく、Claude Code の自動記録（JSONL）から作った。ツールの結果と、Claude の思考は含まない（`records/conversation-a.md` 1〜6 行目）
  - A：時間内（22 分）に終わった。時刻は会話ログの時刻と一致する

## 5. まとめ（ブログに使う事実）

ここには、上の表から根拠を示せることだけを書きます。

- A（AI-DLC なし）では、依頼の直後に AI が確認なしでシナリオ全体を書き、前提の確認は書いた後に行われた（3.2）
- A では、人の入力 13 回のうち 5 回が修正の依頼だった（2 章）
- A では、版ごとの変更の理由は文書内の変更履歴に残ったが、途中の版の中身は残らなかった（3.3）
- A の最終版で、グラフによる可視化の方法は、途中の版にはあったが、文書を短くする際に落ちた（3.1）
- B との比較は、B の列の記入後に書く
